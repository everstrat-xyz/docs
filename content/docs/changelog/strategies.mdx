## 2026-10-01

### UniCL v2 makes better use of inventory

The new implementation sizes swaps for the position’s actual token ratio and uses leftover inventory in an alternate position.

- Deposits can add liquidity without rebuilding the whole position.
- Withdrawals use idle inventory first, then remove the liquidity needed.
- Existing static strategies still require deployment and migration.

**Subsequent mainnet activation:** the v2 registration and v1 removal operations executed on October 19, 2026. [Migration execution and evidence](#2026-10-19).


<details className="change-details">
<summary>Details & sources</summary>

#### UniCLStrat 2.0.0 implementation

**Merged.** Added ratio-aware inventory swaps, an alternate position built from actual leftovers,
and incremental liquidity additions. Withdrawals use idle inventory before partially burning
positions, size swaps against the actual route, and fully unwind near-full withdrawals.
Partial collection rebases the LP-fee snapshot so returned principal does not become performance-fee
income. Shared logic moved into the linked `UniCLStratLib`.

Source: [contracts #53](https://github.com/everstrat-xyz/contracts/pull/53),
[merge 157129b](https://github.com/everstrat-xyz/contracts/commit/157129b7c7f3db06275ecc6697ff0acfab3d9dbe).
Mainnet activation followed through new deployments and the [October 19 migration](#2026-10-19).

</details>

</ChangeEntry>

## 2026-09-22

### Rebalance only when there is work to do

The strategy health check no longer requests a rebalance while a pool is non-calm. Existing instances need migration to receive this implementation change.





<details className="change-details">
<summary>Details & sources</summary>

#### Rebalance health predicate corrected

**Merged.** `isHealthy()` reports no actionable rebalance for paused or non-calm pools.
The rebalance trigger now requires a calm, unpaused, drifted strategy. Deposit capacity still
independently falls to zero when paused or non-calm. This change applies to newly deployed builds;
existing static instances require migration. The interim off-chain mitigation is recorded in
[Automation](/changelog/automation#2026-09-19).

Source: [contracts #51](https://github.com/everstrat-xyz/contracts/pull/51).

</details>

## 2026-08-17

### Stronger strategy recovery and pool checks

Strategy pause and ETH recovery can proceed when a paired token fails.

- Pool configuration must match the trusted factory.
- TWAP history is checked at construction and when settings change.
- Pause is still best-effort recovery, not proof that all assets were recovered.



<details className="change-details">
<summary>Details & sources</summary>

#### Circuit-breaker and pool-validation hardening

**Merged.** Isolated best-effort paired-token allowance revocation and token recovery so a degraded
paired token does not roll back the pause or ETH sweep. Added factory provenance checks for pools,
and construction/configuration checks for TWAP availability and observation cardinality.
Pause remains best-effort recovery; it does not prove that all pool liquidity was recovered.

Source: [contracts #42](https://github.com/everstrat-xyz/contracts/pull/42).

</details>
