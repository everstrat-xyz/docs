## Entry Point

Burns originate from `AMM.exit(requestedEth, maxTokensToBurn, priceTolerance)`.

See the [exit-path diagram](/using-everstrat/exiting-and-redeeming#everstrat-exit-diagram) for the liquidity-dependent branches.

The immediate branch needs unreserved ETH in the AMM. At the
[dated deployment snapshot](/operations/current-deployments#exit-liquidity-at-this-block),
the AMM had none, so new exits take the queued branch.

<Tabs items={["Immediate redemption", "Queued redemption"]}>
  <Tab>
    If the AMM can satisfy the ETH request, the user receives ETH immediately and the lifecycle ends
    in a single transaction.
  </Tab>
  <Tab>
    If the AMM cannot satisfy the request, the AMM records a queue request in `ExitQueue` and emits
    `RedemptionQueued`.
  </Tab>
</Tabs>

## Why Slippage Matters More On Burn

Burn slippage is not just a UI display guard. It becomes protocol `priceTolerance` for queued
redemptions. If the keeper-priced batch falls outside that tolerance, the request can close instead
of redeeming ETH.

`maxTokensToBurn` caps the EVE input before either branch, including queued escrow.
