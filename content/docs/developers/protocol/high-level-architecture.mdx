## Main Components

| Layer | Components | Role |
| --- | --- | --- |
| Immutable core | `EVE`, `AMM` | Token mint/burn and user entry/exit surface |
| Upgradeable management | `Controller`, `ExitQueue`, `StrategyManager`, `Oracle`, `Converter` | Strategy operations, queue state, NAV, valuation, conversion routes |
| Authorization | Registry, Whitelist, Timelock | Peers, roles, invite entry, delayed ADMIN actions |
| Automation | Mimic W1/W2 and keeper executors | Authenticated queue and strategy operations |
| User interface | `everstrat-xyz/app` | Mint/burn, Portfolio, Metrics, transaction UX, account details |
| Data layer | GoldSky subgraph | Activity feed, request history, user aggregates |

See the [contract architecture diagram](/how-everstrat-works/architecture#everstrat-architecture-diagram).

## Key Relationship

<Tabs items={["User action", "Keeper action"]}>
  <Tab>
    Users interact through AMM entry (including invite authorization), exit, cancellation, and claim.
  </Tab>
  <Tab>
    Allowlisted Mimic callers invoke keeper executors, which use Controller to price batches,
    process queued requests, and move funds across strategies.
  </Tab>
</Tabs>

## Core Rule

The hot path is **ETH-first**:

- AMM price calculations are based on ETH NAV.
- Normal enter/exit read NAV, which can depend on Oracle feeds and pool TWAPs.
- Oracle is also used directly for bootstrap USD validation and USD-denominated views.
